# 工业视觉（Industrial Vision）

工业视觉把计算机视觉用在工厂场景：缺陷检测、字符识别、尺寸测量。CodeLab 与企业的合作项目多集中于此。

## 典型任务

| 任务 | 场景 | 说明 |
| --- | --- | --- |
| 缺陷检测 | 表面划痕、污渍、破损 | 样本少、类别极不均衡 |
| OCR / 字符识别 | 生产日期、序列号、标签 | 光照、反光、遮挡干扰大 |
| 定位 / 测量 | 工件定位、尺寸测量 | 精度要求高，需标定 |
| 计数 / 分拣 | 零件计数、按缺陷分拣 | 与产线设备联动 |

## 与学术视觉的区别

- **稳定 > 花活**：漏检代价高，宁可误检也要少漏检
- **样本稀缺**：缺陷样本少，常用数据增强、合成数据、小样本方法
- **现场约束**：光照、震动、速度、成本限制，算法必须适配硬件
- **落地为王**：最终以部署到产线 / 现场为准，不是指标好看

## 标准流程

```text
需求确认（缺陷类型、节拍、精度要求）
  ↓ 采集样本（现场打光、拍照）
  ↓ 标注 + 数据划分
  ↓ 建模（预训练微调 / 传统图像处理）
  ↓ 现场验证（badcase 迭代）
  ↓ 封装服务（FastAPI + Docker）
  ↓ 部署验收 + 文档归档
```

## 工程要点

- **打光是第一位的**：好的光源比好模型更有效，先解决成像
- **缺陷样本要真实**：合成数据辅助，但必须用真实样本验收
- **阈值与可调参数**：交付时要让现场人员能调参，记录默认值
- **性能预算**：算清楚单张推理时间，满足产线节拍
- **异常处理**：模型置信度低时怎么处理（拒识 / 人工复核）

## 交付物

- 代码仓库（训练 + 推理服务）
- 模型文件与版本说明
- 部署文档（Docker 镜像、接口说明、参数表）
- 验收报告（指标、badcase 分析）
