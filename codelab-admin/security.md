# 工程安全基线

本文件说明代码仓库和 CI/CD 的最低安全要求。安全事件和凭据泄露的处理流程见组织级 [SECURITY.md](https://github.com/nynu-codelab/.github/blob/main/SECURITY.md)。

## 仓库安全

- 不提交密码、Token、API Key、SSH Key、证书私钥和真实 `.env`。
- 只提交 `.env.example`，使用空值或占位符。
- 不把生产数据、企业数据、用户隐私或内部截图提交到公开仓库。
- 依赖升级前检查变更、许可证和安全公告。
- 删除敏感文件不能消除 Git 历史中的泄露，必须轮换凭据并清理历史。

## 代码安全

- 所有外部输入都要校验，不能信任客户端或上游服务。
- 数据库查询使用参数化方式，禁止拼接用户输入。
- 日志不记录密码、Token、完整身份证号、手机号或支付信息。
- 错误响应不暴露堆栈、数据库结构、内部路径或密钥。
- 文件上传、命令执行、反序列化和模板渲染等高风险操作必须做白名单和边界检查。
- 权限检查放在服务端，不能只依赖前端隐藏按钮。

## CI/CD 安全

- 工作流使用最小权限，默认 `contents: read`。
- 第三方 Action 固定到受信任版本，重要仓库优先固定到 Commit SHA。
- 不在 Pull Request 的公开日志中输出密钥。
- 发布密钥使用 GitHub Environment、组织 Secret 或部署平台密钥管理，不写入仓库。
- 发布和回滚操作保留审计记录。
- 生产环境变更需要明确审批和回滚方案。

## 依赖与制品

- 使用锁文件保证依赖可复现。
- 定期检查高危漏洞和废弃依赖。
- 构建产物不提交到仓库，使用 Release、包仓库或镜像仓库。
- 容器镜像使用固定基础镜像版本，避免使用不受控的 `latest` 作为生产制品。

## 事件响应

发现疑似泄露或漏洞时：

1. 停止继续传播，保存必要证据。
2. 立即轮换或吊销可能泄露的凭据。
3. 在 Issue 中说明情况：泄露了什么、什么时候轮换的、需要谁协助清理历史。不需要隐瞒；如果是企业合作项目的凭据，改按合作协议约定的渠道处理。
4. 评估影响范围并制定修复和回滚方案。
5. 修复后记录原因、时间线和改进项。
